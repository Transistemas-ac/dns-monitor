Vigila tus dominios las 24/7 y enterate por email si algo cambia: registros DNS, nameservers, vencimiento, DNSSEC y más.

¿Qué vigila? 👀

Todo lo que puede romperse o cambiar en tu dominio, en un solo lugar.

🔄

Cambios en DNS interno

Detecta cualquier registro nuevo, modificado o eliminado en tu zona de Cloudflare, comparando snapshots guardados en KV.
🌐

Nameservers reales

Consulta los nameservers públicos vía DNS over HTTPS y avisa si alguien los cambió por fuera de Cloudflare.
🕵️

¿Quién lo cambió?

Con los Audit Logs de Cloudflare rastreamos qué email hizo cada cambio, con fecha y acción. Sin permiso de logs, se omite sin romper nada.
⏳

Vencimiento del dominio

Consulta la fecha real de expiración vía RDAP (gratis, sin API key) y te alerta a los 60, 30, 14, 7 y 1 día. Detecta renovaciones, cambios de registrador y estados críticos (pendingDelete, redemptionPeriod, clientHold).
✉️

Registros de email

Verifica MX, SPF, DMARC y DKIM. Alerta solo cuando el estado cambia: sin SPF, más de 10 DNS lookups (RFC 7208), DMARC en p=none, sin rua/ruf, registros duplicados, selectores faltantes.
🔐

Estado DNSSEC

Compara el DNSSEC de Cloudflare con los registros DS públicos: DS no propagado, huérfano o mismatch. Tu dominio firmado, sin sorpresas.
💓

Salud del monitor

Heartbeat que detecta corridas perdidas del cron y errores recurrentes por dominio, más ping opcional a Healthchecks para cubrir la muerte total.
📬

Un email, todo junto

Cada dominio tiene su destinatario. Si hay novedades, llega un correo combinado con todas las secciones afectadas. Nada de spam diario.
🛡️

CAA records

Detecta cambios en los registros CAA (quién puede emitir certificados para tu dominio). Opcional: aviso único si no hay CAA con expectCAA: true.
🧭

Nameservers consistentes

Compara las respuestas NS de 1.1.1.1 (Cloudflare) y 8.8.8.8 (Google). Si no coinciden, algo raro está pasando con tu DNS: posible secuestro o fragmentación.
⚡

Registro HTTPS (SVCB)

Sigue el registro HTTPS (tipo 65) del apex: señal de adopción de HTTP/3 y parados de conexión. Alerta ante cualquier cambio o desaparición.
🌐

Web check (opcional)

Con expectWeb: true, verifica que tu sitio responda por HTTPS (timeout 15 s) y avisa si se cae o cambia su estado HTTP. Sin API keys, solo un fetch por corrida.


Cómo funciona 🧠

Un Cloudflare Worker con cron que corre solo, se guarda sus propias comparaciones y solo te molesta cuando hay novedades.

⏰

Se despierta cada 10 minutos

El cron dispara la corrida completa en background. Sin servidores que mantener, sin costos fijos.

📸

Compara snapshots en KV

Obtiene los registros DNS internos y los nameservers reales, y los compara con el estado anterior guardado. Diff determinista y ordenado.

🕵️

Rastrea a la persona responsable

Si hubo cambios DNS, consulta los Audit Logs de la zona desde el último cursor y adjunta quién lo hizo, cuándo y qué acción.

📅

Checks diarios con frescura

Vencimiento, registros de email y DNSSEC corren una vez por día, controlados por timestamps en KV.

📧

Email combinado, solo si hay novedades

Un solo correo con todas las secciones afectadas del dominio, enviado con Resend al destinatario configurado.

💓

Y se vigila a sí mismo

Heartbeat interno para corridas perdidas, contador de errores por dominio con aviso de recuperación, y ping opcional a Healthchecks.



Setup en minutos ⚙️

Instalación con Wrangler, secretos por comando y listo. Tres pasos y tu monitor ya está cuidando tus dominios.

🧰

Requisitos

☁️Cloudflare Workers habilitado y acceso a los dominios a monitorear.
📮Cuenta en Resend con el remitente mailFrom verificado.
🔑Token de Cloudflare con permisos Zone → DNS, Zone y Logs (todos en Read).
🛠️

Instalación

# 1. Clona el repo
git clone https://github.com/Transistemas-ac/dns-monitor
cd dns-monitor

# 2. Instala dependencias
npm install

# 3. Namespace de KV
npx wrangler kv namespace create DNS_MONITOR

# 4. Secretos (Cloudflare y Resend)
npx wrangler secret put CF_API_TOKEN
npx wrangler secret put RESEND_API_KEY

# 5. Deploy 🚀
npx wrangler deploy

✔ Monitor corriendo

Pegá el id del KV y cargá la lista de dominios a monitorear en wrangler.toml: 

kv_namespaces = [
  { binding = "DNS_MONITOR", id = "<id del namespace>" }
]

routes = [
  { pattern = "dns.transistemas.org", custom_domain = true }
]

[vars]
# Lista de dominios a monitorear (recuerda eliminar el default)
DOMAINS = """[
  {
    "zoneId": "<ZONE_ID>",
    "zoneName": "example.com",
    "mailTo": "admin@example.com",
    "mailFrom": "dns@example.com"
  }
]"""
🛡️

Watchdog externo (opcional)

Healthchecks.io
1️⃣Cuenta gratis en healthchecks.io → My Checks → Add Check.
2️⃣Elegí "Ping-only" con Period 10 min y Grace 1 día.
3️⃣Copiá la URL de ping (ej. https://hc-ping.com/<uuid>) y configurala como secreto: 
npx wrangler secret put HEALTHCHECKS_URL
El Worker hace ping al final de cada corrida exitosa. Si el cron muere del todo, Healthchecks te alerta — cubre lo que el heartbeat interno no puede detectar.
